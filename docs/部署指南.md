# GitHub Pages 部署指南

## 自动部署配置

本项目已配置 GitHub Actions 自动部署到 GitHub Pages。

### 配置步骤

#### 1. 启用 GitHub Pages

1. 进入 GitHub 仓库页面
2. 点击 `Settings` (设置)
3. 在左侧菜单找到 `Pages`
4. 在 `Source` 下选择 `GitHub Actions`

#### 2. 推送代码触发部署

```bash
git add .
git commit -m "配置 GitHub Pages 部署"
git push origin main
```

推送到 main 分支后，GitHub Actions 会自动：
1. 安装依赖
2. 构建项目
3. 部署到 GitHub Pages

#### 3. 访问网站

部署完成后，网站将在以下地址访问：

```
https://h1s97x.github.io/RainbowSea/
```

### 工作流程说明

`.github/workflows/deploy.yml` 文件定义了自动部署流程：

- **触发条件**：推送到 main 分支或手动触发
- **构建步骤**：
  1. 检出代码
  2. 设置 Node.js 环境
  3. 安装依赖 (`npm ci`)
  4. 构建项目 (`npm run build`)
  5. 上传构建产物
- **部署步骤**：
  1. 部署到 GitHub Pages

### Vite 配置

`vite.config.js` 中的关键配置：

```javascript
base: process.env.NODE_ENV === 'production' ? '/RainbowSea/' : '/'
```

这确保了：
- 开发环境：使用根路径 `/`
- 生产环境：使用仓库名称 `/RainbowSea/`

### 手动触发部署

1. 进入 GitHub 仓库
2. 点击 `Actions` 标签
3. 选择 `Deploy to GitHub Pages` 工作流
4. 点击 `Run workflow` 按钮
5. 选择 `main` 分支
6. 点击 `Run workflow` 确认

### 查看部署状态

1. 进入 `Actions` 标签
2. 查看最新的工作流运行状态
3. 点击查看详细日志

### 本地构建测试

在推送前，可以本地测试构建：

```bash
# 构建
npm run build

# 预览构建结果
npm run preview
```

### 常见问题

#### 1. 404 错误

如果访问页面出现 404，检查：
- GitHub Pages 是否已启用
- Source 是否设置为 `GitHub Actions`
- base 路径是否正确配置

#### 2. 资源加载失败

如果 CSS/JS 文件加载失败：
- 检查 `vite.config.js` 中的 `base` 配置
- 确保路径包含仓库名称

#### 3. 部署失败

查看 Actions 日志，常见原因：
- 依赖安装失败
- 构建错误
- 权限问题

### 更新部署

每次推送到 main 分支都会自动触发部署：

```bash
git add .
git commit -m "更新内容"
git push origin main
```

等待几分钟后，更改将在线上生效。

### 自定义域名（可选）

如果要使用自定义域名：

1. 在仓库根目录创建 `public/CNAME` 文件
2. 文件内容为你的域名，如：`example.com`
3. 在域名提供商处配置 DNS：
   - 类型：CNAME
   - 名称：www
   - 值：h1s97x.github.io
4. 在 GitHub Pages 设置中添加自定义域名

### 性能优化

已配置的优化：

- **代码分割**：将 Vue、动画库、音频库分别打包
- **资源压缩**：自动压缩 JS、CSS
- **Tree Shaking**：移除未使用的代码
- **懒加载**：路由组件按需加载

### 监控部署

- 部署时间：通常 2-5 分钟
- 构建日志：在 Actions 中查看
- 部署状态：在 Pages 设置中查看

---

**提示**：首次部署可能需要等待几分钟才能访问。后续更新通常在 1-2 分钟内生效。
