## 一、项目背景

《星游记 - Rainbow Sea Journey》动画展示官网。项目最初是一套多页面静态网站（存于 `reference/`，含 5 个 HTML 页面与大量手写 CSS/JS），后由作者 h1s97x 使用 **Vue 3 + Vite** 重构为 SPA，包含首页 / 人物介绍 / 剧情介绍 / 图片画廊 4 个路由页面，并集成了星空背景动画、背景音乐播放器、轮播图、图片灯箱等交互能力。

当前仓库已具备：

- Vue 3 单页应用骨架（`src/` 完整分层：`views / components / composables / router / utils / assets`）
- GSAP + ScrollTrigger 动画体系（`composables/useAnimation.js`）
- Swiper 轮播、Howler 音频、SCSS 样式
- GitHub Pages 自动部署（`.github/workflows/deploy.yml`）

本次优化目标：**在不推倒重来的前提下，补齐工程化短板，让项目可长期维护、可扩展、可协作**。

## 三、技术栈选型

### 3.1 候选方案对比

| 方案                      | 结论        | 核心理由                                                                        |
| ------------------------- | ----------- | ------------------------------------------------------------------------------- |
| **A. Vue 3 生态原地优化** | ✅ **推荐** | 4 个页面已全部在 Vue 3 上，GSAP/Swiper/Howler 已有绑定，零重写成本，见效最快    |
| B. 换 Nuxt 3              | ❌ 过度设计 | 静态展示站不需要 SSR 优先，引入 100+ 依赖复杂度，收益不匹配                     |

> 📌 **Nuxt 3 专项评估**：针对迁移 Nuxt 3 的动机、影响面、SSR 改造难点、路线图与成本收益，已单独产出 [《Nuxt 3 迁移路线评估》](./Nuxt3迁移路线评估.md)，与本文 ADR-001 结论一致：当前不建议迁移，留作未来预案。
| C. 换 Astro               | 🟡 可选     | 内容型网站适合，但动画交互驱动场景下岛屿模型限制 GSAP/Howler 全局玩法，且需重写 |
| D. 换 React/Next          | ❌ 推倒重来 | 与现有 Vue 组件、动画库全部不兼容，成本最高                                     |

> **结论**：本项目瓶颈不在"框架选错"，而在"工程化不完整"。推荐 **原地优化**，把地基与管线补齐，而不是拆房重盖。

### 3.2 推荐技术栈全景

```
┌───────────────────────────────────────────────────────┐
│                      Vue 3.5                           │
│            （Composition API + <script setup>）         │
│  ├── Vue Router 4.x / 5.x（稳定主线）                  │
│  ├── Pinia 4（全局状态：音乐 / 加载 / 偏好）            │
│  ├── TypeScript 5（渐进式，先数据层后视图层）           │
│  ├── SCSS 设计 Token（移除 Bootstrap）                 │
│  ├── GSAP + ScrollTrigger（动画）                      │
│  ├── Swiper（轮播）                                    │
│  ├── Howler.js（音频）                                 │
│  ├── Vite 稳定版（v8 正式版，移除 beta/overrides）      │
│  ├── ESLint 9 + Prettier 3                            │
│  └── Vitest（可选，数据层/工具函数单测）               │
└───────────────────────────────────────────────────────┘
```

## 四、目标架构设计

### 4.1 分层架构总览

```
┌─────────────────────────────────────────────┐
│              视图层 Views                    │
│   Home / Characters / Episodes / Gallery    │
├─────────────────────────────────────────────┤
│              组件层 Components               │
│   layout（Navigation/Footer）               │
│   common（MusicPlayer/LazyImage/Modal/...）  │
│   effects（StarField/...）                  │
├─────────────────────────────────────────────┤
│              状态层 Stores（Pinia）          │
│   music（播放/音量/曲目，持久化）            │
│   loading（真实首屏加载）                   │
│   theme（可选）                             │
├─────────────────────────────────────────────┤
│              数据层 Data + Types             │
│   characters / episodes / gallery / music    │
├─────────────────────────────────────────────┤
│              基础设施层                      │
│   router / composables / directives / utils │
│   styles（tokens/mixins/main）              │
└─────────────────────────────────────────────┘
```

### 4.2 各层职责与依赖方向

- **依赖单向**：视图 → 组件 → 状态层 → 数据层 → 基础设施层。
- **数据层**：只负责内容定义（角色/剧集/画廊/音乐），可平滑替换为 JSON 或后端接口。
- **状态层**：全局单例，跨页面共享，负责可持久化的运行态（音乐播放、加载、偏好）。
- **动画层**：用 `v-reveal` 指令统一"进入视口才播"的滚动动画，避免每个页面重复写 `onMounted + gsap.from`。
- **样式层**：单一设计 Token 源（颜色/字体/间距/断点/动效曲线），组件禁止硬编码色值。

## 六、各层设计规范

### 6.1 数据层（`src/data/`）

- 每个数据模块导出**强类型**数组/常量，供视图消费。
- 图片路径统一经 `resolveAssetUrl` 工具拼接 `BASE_URL`，兼容子路径部署。
- 命名规范：`characters.ts`、`episodes.ts`、`gallery.ts`、`music.ts`。
- 后续可平滑替换为 `fetch('/api/xxx')` 或 `import xxx from './xxx.json'`。

### 6.2 状态层（Pinia）

**music store**：

```ts
interface MusicState {
  currentTrack: MusicTrack | null
  isPlaying: boolean
  currentTime: number
  duration: number
  volume: number // 持久化到 localStorage
  playlist: MusicTrack[]
}
```

- `loadTrack / play / pause / togglePlay / seek / setVolume / next / prev`
- 挂载时从 `localStorage` 恢复音量与上次曲目，实现跨页共享。

**loading store**：

- 监听首屏关键资源（`window.load` 或首屏图片加载完成）后关闭，替代固定 2 秒假加载。

### 6.3 动画层（`v-reveal` 指令）

```ts
// 用法示例
<div v-reveal="{ y: 50, delay: 0.2 }">...</div>
```

- 基于 `IntersectionObserver`，元素进入视口时播放 `gsap.from` 动画，播放后自动解绑。
- 组件卸载时统一 `gsap.context.revert()` 清理，避免动画泄漏。
- `useReveal` composable 保留给需要手动控制的复杂场景。

### 6.4 样式层（设计 Token）

```scss
// tokens.scss
$color-primary: #4a90e2;
$color-secondary: #f39c12;
$color-accent: #e74c3c;
$color-bg: #000;
$color-text: #fff;
$font-family-base: 'Fredericka the Great', cursive, sans-serif;
$spacing: (
  xs: 0.5rem,
  sm: 1rem,
  md: 1.5rem,
  lg: 2rem,
  xl: 3rem
);
$breakpoints: (
  sm: 576px,
  md: 768px,
  lg: 992px,
  xl: 1200px
);
$transition-base: all 0.3s ease;
```

- 组件内**禁止硬编码色值**，统一引用 token。
- 移除 Bootstrap CSS，全局基础样式收敛到 `styles/main.scss`。

### 6.5 类型层（TypeScript 渐进式）

- **P2 阶段**：`types/` + `data/` + `stores/` + `router/` 全部 TS。
- **P3 阶段**：`composables/`、`components/`、`views/` 逐步迁移。
- 使用 `vue-tsc` 做模板类型检查，`npm run type-check` 纳入 CI。

## 十、决策记录（ADR）

### ADR-001：坚守 Vue 3 原地优化，不换框架

- **状态**：已采纳
- **背景**：用户询问是否用新技术栈重写。
- **决策**：保留 Vue 3.5 + Vite 生态，补齐工程化。
- **理由**：零重写成本、动画库绑定已就绪、瓶颈在工程化而非框架。
- **后果**：放弃 SSR/SEO 收益（展示站可接受）。

### ADR-002：Vite 使用稳定正式版，移除 beta 与 overrides

- **状态**：已采纳
- **背景**：`vite@8.0.0-beta.13` + `overrides` 强制锁定。
- **决策**：升级到 `vite@^8.2.x`，删除 `overrides`。
- **理由**：消除构建链不确定性；`@vitejs/plugin-vue@6` 与 `vite@8` peer 兼容。

### ADR-003：移除 Bootstrap

- **状态**：已采纳
- **背景**：仅引入 CSS，零组件使用。
- **决策**：彻底移除，改用 SCSS 设计 Token。
- **理由**：首屏 CSS 减量、单一样式源。
- **后果**：需要确认无隐藏依赖 Bootstrap 类名（调研无）。

### ADR-004：引入 Pinia 统一全局状态

- **状态**：已采纳
- **背景**：音乐播放状态跨页不共享。
- **决策**：Pinia 管理 music/loading，音量持久化。
- **理由**：官方推荐、TS 友好、DevTools 支持。

### ADR-005：TypeScript 渐进式引入

- **状态**：已采纳（P2 先数据/状态层）
- **背景**：全项目 JS，无类型约束。
- **决策**：先迁移 `types/data/stores/router`，视图层后续。
- **理由**：成本可控、立即获得数据层安全。
